# Docconv Internal Library - Architecture & Development

## Overview

`docconv` is a pure-stdlib document conversion library used internally for PDF text/table extraction and OOXML format generation. It has no external dependencies beyond Python's standard library.

## Architecture Layers

### 1. PDF Parsing Layer
- **`_obj.py`**: PDF bytecode lexer and object tokenization
- **`_xref.py`**: Cross-reference table resolution and object indexing
- **`_page.py`**: Page structure loading and resource resolution
- **`_filter.py`**: Stream filter chain decoding (Flate, LZW, ASCII85, etc.)
- **`_content.py`**: Content stream execution (text, graphics, paths)

### 2. Content Extraction Layer
- **`_font.py`**: Font decoding, encoding resolution (WinAnsi, ToUnicode)
- **`textlayout.py`**: Glyph-to-line-to-paragraph reconstruction
- **`table.py`**: Table detection (ruled + unruled strategies)

### 3. Format Writers
- **`pdfwrite.py`**: Text-only PDF generation (fallback for Office→PDF)
- **`word.py`**: DOCX/OOXML writer
- **`excel.py`**: XLSX/OOXML writer
- **`slides.py`**: PPTX/OOXML writer
- **`_ooxml.py`**: Shared OOXML plumbing (ZIP, XML, relationships)
- **`imgcodec.py`**: PNG/JPEG I/O and image wrapping

### 4. Public API
- **`pdf.py`**: Main extraction API (`extract_pages()`, `PageContent`)
- **`__init__.py`**: Package exports

## Development Guidelines

### Error Handling
- Raise `PdfReadError` for unreadable PDFs (not `ValueError` or cryptic errors)
- Raise `PdfEncryptedError` for encrypted PDFs (not opaque exceptions)
- Raise format-specific errors: `ImageError`, `ExcelError`, `OoxmlError`
- All error messages should be in clear, actionable Indonesian or English

### Performance Considerations
- Content stream parsing (_content.py) is the bottleneck for large PDFs
- Lazy evaluation: don't extract text until `extract_pages()` is called
- Fonts are cached per-page to avoid repeated resolution
- Table detection is conservative: ambiguous cases stay as text

### Testing Strategy
- Unit tests in `tests/test_docconv.py` (core functionality)
- Robustness tests in `tests/test_docconv_robustness.py` (edge cases)
- Fixtures in `tests/fixtures/` generated by `make_fixtures.py` (cross-validation with reportlab)

### Code Style
- Concise, focused docstrings (no stage references or verbose explanations)
- Type hints for public APIs
- Helper functions prefixed with `_` for internal use
- Class `__slots__` for memory efficiency (often deals with large documents)

## Known Limitations & Future Work

### Current Limitations
- No PDF encryption/decryption support
- Limited styling preservation (basic font info only)
- No hyperlink extraction
- Image-only pages trigger OCR fallback (if available)
- Table confidence scoring not exposed

## Maintenance Notes

1. **When updating _filter.py**: Ensure round-trip tests pass (flate, LZW, ASCII85 codecs)
2. **When updating _font.py**: Validate against WinAnsiEncoding and custom font encodings
3. **When updating table.py**: Test both ruled (grid lines) and unruled (gap-based) detection
4. **When updating _ooxml.py**: Ensure Office 2010+ compatibility for DOCX/XLSX/PPTX

## Running Tests

```bash
# Core functionality (requires fixtures)
python -m pytest tests/test_docconv.py -v

# Robustness tests (no fixtures needed)
python -m pytest tests/test_docconv_robustness.py -v

# Generate fixtures (one-time setup)
python tests/make_fixtures.py

# Specific test
python -m pytest tests/test_docconv.py::test_ruled_table_is_detected_as_a_grid -v
```
